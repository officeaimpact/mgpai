## Внедрённые правки

### Правка A: Ограничение early pass в `_check_cascade_slots`

**Файл:** `backend/yandex_handler.py`  
**Проблема:** Модель выдумывала `stars`/`meal` на первом поиске, early pass пропускал проверку QC по тексту пользователя.

**Изменения:**
1. Сигнатура `_check_cascade_slots` — добавлен параметр `is_follow_up=False`
2. Early pass (строка 450) — добавлено условие `is_follow_up and` перед проверкой параметров
3. Вызов (строка 1847) — передаётся `is_follow_up=bool(self._last_search_params)`

**Дополнительный фикс (обнаружен в ходе тестирования):**  
Проблема: модель могла задать QC-вопрос в тексте одновременно с tool call (get_current_date), и сразу вызвать search_tours — `qc_asked=True` срабатывал без реального ответа пользователя.  
Решение: добавлена проверка наличия сообщения пользователя ПОСЛЕ QC-вопроса ассистента. Если пользователь ещё не ответил — `qc_asked` сбрасывается в `False`.

**Вынесение departure_patterns в модульную константу `_DEPARTURE_PATTERNS`** для переиспользования в Правке C.

### Правка B: Переформулировка Правки 6 (regions)

**Файл:** `system_prompt.md`  
**Было:** `НЕ передавай regions вообще (API покажет отели со всей страны).`  
**Стало:** `НЕ передавай regions и НЕ спрашивай про курорт. Просто ищи по всей стране без regions.`

### Правка C: Safety-net для hot tours — город вылета

**Файл:** `backend/yandex_handler.py`  
**Логика:** Перед API-вызовом `get_hot_tours` проверяется текст пользователя на наличие города вылета через `_DEPARTURE_PATTERNS`. Если не найден — возвращается ошибка с инструкцией спросить город.

### Правка D: Safety-net для hot tours — 0 результатов

**Файл:** `backend/yandex_handler.py`  
**Логика:** После API-вызова `get_hot_tours`, если `len(tours) == 0` — ранний return с `_hint` для честного ответа клиенту. Предотвращает ситуацию, когда модель говорит "Нашёл!" при 0 результатах.

### Правка E: Pipeline enforcement для search_tours

**Файлы:** `backend/yandex_handler.py`, `backend/openai_handler.py`

**E1 — Усиление message:**  
Результат `search_tours` теперь содержит явный запрет: `⛔ Поиск запущен... ОБЯЗАТЕЛЬНО сейчас вызови get_search_status... Ты ещё НЕ знаешь результатов — НЕ говори клиенту 'Нашёл'...`

**E2 — Code safety-net:**
- Флаг `self._search_awaiting_results` устанавливается в `True` после `search_tours`
- Сбрасывается в `False` после `get_search_results`
- В main loop `openai_handler.py`: если модель остановилась без `get_search_results`, инжектируется системное сообщение с nudge для продолжения pipeline (до 3 попыток)
