# Отчет: Полное UI-тестирование чат-виджета MGP AI

**Дата:** 22 февраля 2026  
**Тип:** Пользовательское тестирование + глубокий анализ кода фронтенда  
**Версия:** Production Version with Rich Tour Cards

---

## Сценарий тестирования

1. Открытие чата → отправка запроса "Хочу тур в Турцию на двоих на 7 ночей, все включено, бюджет до 200000 руб, вылет из Москвы в марте"
2. Диалог с ботом (уточняющие вопросы: даты, категория отеля, количество гостей)
3. Получение 5 карточек туров в Турцию (цены 86 017 – 89 923 ₽)
4. Нажатие кнопки "Показать ещё"
5. Запрос "А покажите такие же варианты но в Египет" → получение 5 карточек в Египет
6. Нажатие кнопки "Забронировать через чат" → бот актуализирует тур
7. Закрытие/переоткрытие чата

## КРИТИЧЕСКИЕ ОШИБКИ (блокируют нормальную работу)

### C1. Конфликт DOM-элементов при повторном поиске туров

**Файл:** `frontend/script.js`, строки 459-461, 482, 499-500  
**Суть:** При получении второго набора карточек (Египет после Турции) создаются элементы с теми же `id="tourCardsContainer"` и `id="tourCardsWrapper"`. Функции `showMoreCards()` и `scrollCards()` используют `document.getElementById()`, который всегда возвращает ПЕРВЫЙ элемент с данным ID (карточки Турции).

**Последствие:**
- Кнопка "Показать ещё" на карточках Египта добавит оставшиеся карточки в контейнер Турции (сверху, а не снизу)
- Стрелки навигации карусели для Египта будут прокручивать карусель Турции
- Глобальная переменная `allTourCards` перезаписывается на карточки Египта, поэтому при нажатии "Показать ещё" на Турции — покажутся карточки Египта

**Воспроизведение:** Получить карточки Турции → запросить карточки Египта → нажать "Показать ещё" на Египте

---

### C2. XSS-уязвимость в сообщениях чата

**Файл:** `frontend/script.js`, строки 212-234 (функция `createMessageHTML`)  
**Суть:** Сообщения пользователя и бота проходят через `parseFormatting()` без предварительного экранирования HTML. Функция `parseFormatting()` не вызывает `escapeHtml()`, хотя та определена в коде. Содержимое вставляется через `insertAdjacentHTML`.

**Последствие:** Ввод `<img src=x onerror=alert(1)>` в чат выполнит произвольный JavaScript. Поскольку бот использует LLM, существует теоретический вектор атаки через prompt injection.

**Исправление:** Вызывать `escapeHtml(content)` ДО `parseFormatting()` в `createMessageHTML`.

## СЕРЬЕЗНЫЕ ОШИБКИ (значительно ухудшают UX)

### M1. Стрелки навигации карусели обрезаются внутри виджета

**Файл:** `frontend/styles.css`, строки 507-513 и 516-523  
**Суть:** Стрелки карусели позиционированы как `.nav-prev { left: -18px }` и `.nav-next { right: -18px }`, то есть выходят за границы контейнера на 18px. Контейнер `.chat-messages` имеет `overflow-y: auto`, что в большинстве браузеров неявно активирует `overflow-x: auto`, обрезая стрелки. Левая стрелка может частично уходить под аватар бота.

**Последствие:** Стрелки навигации обрезаются или перекрываются, пользователь не может ими пользоваться.

---

### M2. Внутренние коды [b2b] отображаются пользователям в типе номера

**Данные из API:**
```
room_type: "standard room [b2b]"
room_type: "standard room land view [b2b]"
```

**Файл:** `frontend/script.js`, строка 274, 347  
**Суть:** Значение `room_type` из API выводится как есть, без очистки от внутренних кодов операторов.

**Последствие:** Пользователь видит непонятные метки `[b2b]`, `[B2B]` в информации о номере, что выглядит непрофессионально.

---

### M3. Отсутствует цена за человека на карточках

**Данные из API:** `price_per_person: null` для всех карточек  
**Файл:** `frontend/script.js`, строки 359-363  
**Суть:** Секция "за человека" условно рендерится только при наличии `price_per_person`, но API его не передает. При этом `price` — это цена за весь тур на двоих. Пользователь видит только общую цену без пояснения "на двоих".

**Последствие:** Пользователь может подумать, что цена указана за одного человека.

---

### M4. Нет кнопки "Получить ещё туры" (запрос дополнительных туров с сервера)

**Суть:** Кнопка "Показать ещё" (которая есть) лишь раскрывает скрытые карточки из текущей выдачи. Нет механизма запросить следующую страницу результатов или больше туров от API. Пользователь, который хочет больше вариантов, должен сам набрать сообщение.

---

### M5. Потеря рейтинга отеля при ошибке загрузки изображения

**Файл:** `frontend/script.js`, строки 298-299  
**Суть:** `onerror` обработчик изображения заменяет весь `innerHTML` родительского контейнера `.tour-card-image-container`. Но в замене восстанавливается только badge со звёздами, а badge с рейтингом (`tour-card-rating`) НЕ восстанавливается.

**Код:**
```javascript
onerror="this.onerror=null; this.classList.add('placeholder'); 
  this.parentElement.innerHTML='<div class=\\'tour-card-image placeholder\\'>🏨</div>
  <div class=\\'tour-card-badge\\'>${starsDisplay}</div>';"
// ← Потерян: <div class="tour-card-rating">${rating.toFixed(1)}</div>
```

**Последствие:** Если изображение не загрузится, числовой рейтинг отеля (4.1, 4.4 и т.д.) исчезает с карточки.

---

### M6. Длительное ожидание без информативного индикатора прогресса

**Суть:** Поиск туров занимает 10-60 секунд (в тесте: 19-58 секунд). Единственная обратная связь — анимированные точки typing indicator. Пользователь не понимает, что идёт поиск, и может решить, что система зависла.

**Рекомендация:** Добавить текстовый индикатор "Ищу лучшие предложения..." или прогресс-бар.

---

### M7. Неправильная плюрализация в кнопке "Показать ещё"

**Файл:** `frontend/script.js`, строки 411, 446  
**Суть:** Используется упрощённая логика:
```javascript
remainingCount === 1 ? 'тур' : remainingCount < 5 ? 'тура' : 'туров'
```
Это работает для 1-10, но сломано для чисел 21 ("тур"), 22-24 ("тура"), 31 ("тур") и т.д. Аналогично — в строке "Найдено N туров". В то же время `getNightsWord()` (строка 105) реализована правильно.

---

### M8. Отсутствие восстановления после ошибки сети

**Файл:** `frontend/script.js`, строки 611-614  
**Суть:** При ошибке API выводится текстовое сообщение, но нет кнопки "Повторить" или механизма retry. Пользователь должен заново набирать сообщение.

---

## НЕЗНАЧИТЕЛЬНЫЕ ОШИБКИ (мелкие недочёты UX)

### m1. Подсказка "← листайте →" показывается даже когда все карточки видны

**Файл:** `frontend/script.js`, строка 447  
**Суть:** Подсказка `<span class="swipe-hint">← листайте →</span>` отображается при `cardsToShow.length > 1`, но если отображаются всего 2 карточки шириной 240px, они могут помещаться в окно без прокрутки (на широком экране). Подсказка вводит в заблуждение.

---

### m2. Неиспользуемые переменные в коде карточки

**Файл:** `frontend/script.js`  
- Строка 254: `operator` извлекается, но не используется в HTML
- Строка 273: `foodCode` извлекается, но не используется в HTML

---

### m3. CSS-правило для несуществующего класса

**Файл:** `frontend/styles.css`, строка 1061  
```css
.tour-cards-wrapper.horizontal .tour-card { ... }
```
Класс `.horizontal` нигде не добавляется в JavaScript.

---

### m4. Анимация карточек без `animation-fill-mode`

**Файл:** `frontend/styles.css`, строки 1148-1155  
**Суть:** Карточки анимируются через `cardSlideIn` с начальным `opacity: 0`. Карточки с `animation-delay` (2-я, 3-я и т.д.) могут мигнуть перед началом анимации, так как `animation-fill-mode: backwards` не установлен.

---

### m5. Потеря чата при перезагрузке страницы

**Файл:** `frontend/script.js`, строки 28, 674-675  
**Суть:** `conversationId` генерируется заново при каждой загрузке страницы. Вся история диалога теряется. Нет сохранения в `localStorage`.

---

### m6. Нет ограничения длины вводимого сообщения

**Файл:** `frontend/script.js`, строка 561  
**Суть:** Проверяется только `text.trim()`, но нет ограничения по длине. Пользователь может отправить очень длинное сообщение, что может вызвать проблемы с отображением и нагрузкой на API.

---

### m7. Кнопка "Забронировать через чат" использует `onclick` inline handler

**Файл:** `frontend/script.js`, строка 370  
```html
<button class="btn-details" onclick="window.MGPChat.bookTour('${escapeHtml(hotelName)}')">
```
Inline event handlers — плохая практика (CSP, поддержка, безопасность). Лучше использовать делегирование событий.

---

### m8. `hotel_rating.toFixed(1)` без проверки типа

**Файл:** `frontend/script.js`, строка 302  
**Суть:** Если `rating` окажется строкой или неожиданным типом, вызов `.toFixed(1)` упадёт с ошибкой. В текущем API рейтинги приходят числами, но защитного кода нет.

---

## КОСМЕТИЧЕСКИЕ ЗАМЕЧАНИЯ

### K1. Метка "за тур" без уточнения количества гостей

**Строка 288:** `const priceLabel = isHotelOnly ? 'за проживание' : 'за тур';`  
Было бы информативнее: "за тур на 2 чел." — чтобы пользователь понимал, что цена включает двоих.

---

### K2. Тип питания отображается как полная строка "AI - Все Включено"

API возвращает `meal_description: "AI - Все Включено"`, а `food_type` пустой. Код отображает `meal_description`, но формат "AI - ..." выглядит как внутренний код. Лучше отображать только "Все Включено" без кода.

---

### K3. Подвал "Powered by MGP AI" занимает место

**Файл:** `frontend/styles.css`, строка 984-994  
В ограниченном пространстве виджета (650px высоты) подвал с "Powered by MGP AI" отнимает ~25px. Можно сделать его менее заметным.

---

### K4. Имена отелей в верхнем регистре выглядят агрессивно

Данные из API: `LAKE & RIVER SIDE HOTEL & SPA`, `AMARINA SUN RESORT & AQUA PARK (EX. RAOUF HOTELS...)`.  
CSS-класс `.tour-card-hotel` (строка 644) не преобразует текст. Можно добавить `text-transform: capitalize` или обработать в JS для более приятного отображения.

---

### K5. Очень длинные названия отелей в карточках

Пример: `AMARINA SUN RESORT & AQUA PARK (EX. RAOUF HOTELS INTERNATIONAL AQUA PARK & SPA RESORT SUN)` — 98 символов. CSS ограничивает `-webkit-line-clamp: 2`, но на карточке 240px шириной даже 2 строки могут быть недостаточно, и название обрезается без видимого многоточия на некоторых браузерах.

3. **M2** — Очищать `room_type` от `[b2b]` и подобных внутренних меток
4. **M5** — Восстанавливать рейтинг в onerror handler

5. **M6** — Добавить информативный индикатор поиска
6. **M7** — Использовать правильную функцию плюрализации (как в `getNightsWord`)
7. **M1** — Перепозиционировать стрелки карусели внутрь контейнера
8. **M3** — Рассчитывать и показывать цену за человека
9. **M8** — Добавить кнопку "Повторить" при ошибках

### Среднесрочные улучшения:
10. **m5** — Сохранять историю чата в localStorage
11. **m4** — Добавить `animation-fill-mode: backwards` для карточек
12. **K2** — Очищать код типа питания (убирать "AI - " из начала)
13. **K4** — Преобразовывать UPPERCASE имена отелей
