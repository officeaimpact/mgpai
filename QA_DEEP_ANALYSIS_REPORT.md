## 2. КРИТИЧЕСКИЕ БАГИ

### BUG-01: Кисловодск → результаты из Санкт-Петербурга и Сочи

**Сессия:** `da15cecc` (Feb 8, 17:03)

**Запрос клиента:** `"Кисловодск 7 дней 2 взрослых 15 октября"`

**Что произошло:**
```
search_tours(adults=2, country=47, datefrom=15.10.2026, dateto=22.10.2026, departure=1, nightsfrom=7, nightsto=7)
```
- Модель НЕ передала `regions` — поиск по ВСЕЙ России
- Результаты: отели в Санкт-Петербурге, Сочи — НИ ОДНОГО в Кисловодске
- Модель ответила: «Нашёл отличные варианты в Кисловодске» — **ЛОЖНОЕ УТВЕРЖДЕНИЕ**

**Корневая причина:**
1. Модель подставила `departure=1` (Москва) без вопроса клиенту — нарушение правила 0.0.2
2. Каскадный валидатор **НЕ заблокировал** вызов (должен был — нет departure в тексте, нет QC)
3. Auto-resolve для Кисловодска (`resort_patterns`) **НЕ сработал** — возможно, паттерн не проверился, или проверка пропущена по условиям гонки

**Тяжесть:** Катастрофическая — клиент получил ПОЛНОСТЬЮ нерелевантные результаты + ложное утверждение ассистента.

### BUG-02: Кисловодск — сессия зависла

**Сессия:** `ee3bb7f8` (Feb 9, 13:18)

**Тот же запрос:** `"Кисловодск 7 дней 2 взрослых 15 октября"`

**Что произошло:**
1. Модель вызвала `get_dictionaries(regcountry=47, type="region")` → получила ПОЛНЫЙ список регионов России
2. Модель вызвала `get_dictionaries(name="Кисловодск", regcountry=47, type="region")` — но API regions **не поддерживает фильтр по name** → получила тот же полный список
3. Модель вызвала `get_dictionaries` **ещё раз** с теми же параметрами → тот же результат
4. Модель ответила: «Подождите, ищу код региона» — и **зависла**
5. Клиент написал «ну что?» → пустой ответ
6. Клиент написал «?» → «Произошла ошибка. Попробуйте начать новый чат.»

**Корневая причина:**
1. API `get_dictionaries(type=region)` **не поддерживает** фильтр `name` — это работает только для `type=hotel`
2. Модель не смогла найти «Кисловодск» в списке регионов, потому что Кисловодск — это **город внутри** региона «Кав. Мин. Воды» (ID=424)
3. Auto-resolve (Tier 2) для Кисловодска → parent_region = «Кавказские Минеральные Воды» — API вернул «Кав. Мин. Воды». **Несоответствие имён** → Tier 2 не нашёл совпадение
4. Модель ушла в зацикливание, потом в пустой ответ

**Тяжесть:** Критическая — мёртвая сессия, клиент потерян.

**Конкретный баг в коде (`yandex_handler.py`, строка ~835):**
```python
if r.get("name", "").lower().strip() == parent_region.lower().strip():
```
Сравнение `"кав. мин. воды"` vs `"кавказские минеральные воды"` → **НЕ совпадает** (точное сравнение, нет fuzzy-match).

## 5. КОРНЕВЫЕ ПРИЧИНЫ

### RC-1: Tier 2 Auto-Resolve использует ТОЧНОЕ сравнение имён

**Файл:** `yandex_handler.py`, ~строка 835
```python
if r.get("name", "").lower().strip() == parent_region.lower().strip():
```
API возвращает `"Кав. Мин. Воды"`, а в коде записано `"Кавказские Минеральные Воды"` → **не матчит**.

**Решение:** Использовать fuzzy-match (содержит подстроку) или добавить алиасы.

### RC-2: get_dictionaries(type=region) не поддерживает name-фильтр

Модель пытается фильтровать `get_dictionaries(type=region, name="Кисловодск")`, но параметр `name` работает ТОЛЬКО для `type=hotel`. Результат: возврат полного списка, модель не может найти нужный регион.

**Решение:** Добавить серверную фильтрацию в `_dispatch_function` для type=region с name-фильтром.

### RC-3: Cascade validator пропускает resort-without-region

Валидатор `_check_cascade_slots` проверяет слоты 2-5, но **НЕ проверяет** соответствие `regions` запрошенному курорту. Auto-resolve в `search_tours` handler должен это ловить, но:
- В некоторых случаях resort_patterns не матчат (Пхукет → проблема с регистром/транслитерацией?)
- В некоторых случаях auto-resolve просто не срабатывает (тайминг, порядок проверок)

### RC-4: Модель пропускает обязательные параметры function calls

YandexGPT иногда «забывает» передать обязательные параметры:
- `type` в `get_dictionaries` (2 случая)
- `regions` в `search_tours` (3 случая)
- Правильный `departure` код (1 случай)

**Решение:** Серверная автокоррекция на стороне `_dispatch_function`.

### RC-5: Каскадный валидатор слишком агрессивен для мульти-странового поиска

При поиске по 3 странам модель запускает 3 параллельных `search_tours`. Каждый проходит через cascade validator ОТДЕЛЬНО, каждый генерирует свою ошибку. Модель видит 3 одинаковые ошибки и иногда «теряется».
